# 智慧医院系统设计规范 v2.0 / Smart Hospital System Design Specification v2.0

## 项目概述 / Project Overview

**项目名称**: 智慧医院系统 / Smart Hospital System  
**项目类型**: Web应用系统 / Web Application System  
**技术栈**: Java + Spring Boot/Cloud + Vue.js + Elasticsearch  
**目标用户**: 学校、工厂、监狱等不便去医院的人群 / People in schools, factories, prisons, etc. who have difficulty accessing hospitals  
**核心功能**: AI医疗诊断、健康档案管理、症状自测、多轮对话、数据安全保障 / AI medical diagnosis, health records management, symptom self-assessment, multi-round dialogue, data security

## 业务需求 / Business Requirements

### 1. 项目背景 / Project Background
- **问题描述**: 偏远地区、特殊场所人员就医困难，医疗资源分布不均
- **解决方案**: 线上AI医疗辅助系统，整合医生诊断经验，提供智能诊断和健康档案管理
- **核心价值**: 降低就医门槛，提高医疗资源利用效率，保障用户数据安全
- **Problem Description**: People in remote areas and special locations have difficulty accessing medical care, uneven distribution of medical resources
- **Solution**: Online AI medical assistance system integrating doctor diagnostic experience, providing intelligent diagnosis and health records management
- **Core Value**: Lower barriers to medical care, improve utilization of medical resources, ensure user data security

### 2. 用户角色 / User Roles

#### 游客 (Visitor)
- **特点**: 未注册用户，只能浏览基本信息和使用症状自测工具
- **目标**: 了解系统功能，注册成为用户
- **Features**: Unregistered users, can only browse basic information and use symptom self-assessment tools
- **Goal**: Understand system features, register as users

#### 用户 (User)
- **特点**: 普通注册用户，拥有健康档案，需要医疗服务
- **目标**: 使用AI医生功能，获取诊断报告，管理健康档案
- **Features**: Ordinary registered users with health records, needing medical services
- **Goal**: Use AI doctor function, obtain diagnostic reports, manage health records

#### 医生 (Doctor)
- **特点**: 经过认证的医疗专业人员，可查看患者档案和诊疗统计
- **目标**: 贡献专业知识，审核医疗内容，管理诊疗数据
- **Features**: Certified medical professionals, can view patient records and diagnosis statistics
- **Goal**: Contribute professional knowledge, review medical content, manage diagnosis data

#### 管理员 (Administrator)
- **特点**: 系统管理人员，拥有最高权限，负责内容审核
- **目标**: 管理整个系统，维护数据质量，确保合规运营
- **Features**: System administrators with highest privileges, responsible for content review
- **Goal**: Manage entire system, maintain data quality, ensure compliant operations

## 功能需求 / Functional Requirements

### 1. 用户管理模块 / User Management Module

#### 注册功能
- **邮箱验证**: 注册时需要邮箱接收验证码
- **角色选择**: 可选择注册为普通用户或医生
- **医生认证**: 医生注册需验证执业资格信息
- **实名认证**: 医生必须使用真实姓名
- **Email Verification**: Email verification code required during registration
- **Role Selection**: Can register as ordinary user or doctor
- **Doctor Verification**: Doctor registration requires practice qualification verification
- **Real Name Authentication**: Doctors must use real names

#### 登录功能
- **账号密码登录**: 支持用户名/邮箱+密码登录
- **会话管理**: JWT令牌管理用户会话
- **安全防护**: 密码加密存储，登录失败限制，操作审计日志
- **Account/Password Login**: Supports username/email + password login
- **Session Management**: JWT token manages user sessions
- **Security Protection**: Password encrypted storage, login failure restrictions, operation audit logs

#### 个人资料管理
- **基本信息**: 姓名、年龄、手机号、头像
- **医生信息**: 执业资格、专业领域、职称
- **密码修改**: 支持密码修改功能
- **Basic Information**: Name, age, phone number, avatar
- **Doctor Information**: Practice qualifications, professional field, title
- **Password Change**: Supports password change function

### 2. 健康档案模块 / Health Records Module

#### 健康档案管理
- **档案创建**: 用户可创建个人健康档案
- **病史记录**: 记录既往病史、手术史、住院史
- **过敏史**: 记录药物过敏、食物过敏等信息
- **用药记录**: 记录正在使用或曾经使用的药物
- **家族病史**: 记录家族遗传病史
- **档案更新**: 支持随时更新健康档案信息
- **Records Creation**: Users can create personal health records
- **Medical History**: Record past medical history, surgery history, hospitalization history
- **Allergy History**: Record drug allergies, food allergies, etc.
- **Medication Records**: Record currently used or previously used medications
- **Family History**: Record family genetic medical history
- **Records Update**: Support updating health records at any time

#### 档案应用
- **AI诊断辅助**: AI诊断时自动参考用户健康档案
- **医生查看**: 经授权的医生可查看患者健康档案
- **隐私保护**: 敏感信息进行脱敏处理
- **AI Diagnosis Assistance**: AI automatically references user health records during diagnosis
- **Doctor Access**: Authorized doctors can view patient health records
- **Privacy Protection**: Sensitive information is desensitized

### 3. 症状自测模块 / Symptom Self-assessment Module

#### 症状问卷
- **系统分类**: 按人体系统分类（呼吸系统、消化系统、循环系统等）
- **结构化选择**: 提供结构化的症状选项，避免自由输入的歧义
- **智能引导**: 根据已选症状智能推荐相关症状
- **严重程度**: 评估症状严重程度
- **System Classification**: Classified by body system (respiratory, digestive, circulatory, etc.)
- **Structured Selection**: Provide structured symptom options to avoid ambiguity of free input
- **Intelligent Guidance**: Intelligently recommend related symptoms based on selected symptoms
- **Severity Assessment**: Assess severity of symptoms

#### 自测结果
- **初步评估**: 基于症状提供初步健康评估
- **就医建议**: 根据严重程度建议是否就医
- **AI对接**: 自测结果可直接传递给AI医生进行深度诊断
- **Preliminary Assessment**: Provide preliminary health assessment based on symptoms
- **Medical Advice**: Recommend whether to seek medical care based on severity
- **AI Integration**: Self-assessment results can be directly passed to AI doctor for in-depth diagnosis

### 4. 用户收藏模块 / User Favorites Module

#### 收藏功能
- **收藏类型**: 支持收藏疾病、药品、健康资讯
- **快速访问**: 收藏内容可在个人中心快速访问
- **分类管理**: 按类型分类展示收藏内容
- **取消收藏**: 支持取消已收藏的内容
- **Favorite Types**: Support bookmarking diseases, drugs, health information
- **Quick Access**: Bookmarked content can be quickly accessed in personal center
- **Category Management**: Display bookmarked content by type
- **Unfavorite**: Support removing bookmarked content

### 5. 智能医生模块 / AI Doctor Module

#### 多轮对话能力
- **上下文理解**: 支持多轮对话，理解对话上下文
- **追问澄清**: AI可主动追问以获取更准确的诊断信息
- **对话历史**: 保存完整对话历史，支持查看和继续
- **Context Understanding**: Support multi-round dialogue, understand conversation context
- **Follow-up Clarification**: AI can proactively ask follow-up questions for more accurate diagnosis
- **Conversation History**: Save complete conversation history, support viewing and continuing

#### 历史诊断记录
- **记录保存**: 自动保存所有诊断对话记录
- **记录查询**: 支持按时间、症状等条件查询历史记录
- **对比分析**: 支持对比不同时间点的诊断记录
- **导出功能**: 支持导出历史诊断记录
- **Records Saving**: Automatically save all diagnosis conversation records
- **Records Query**: Support querying historical records by time, symptoms, etc.
- **Comparison Analysis**: Support comparing diagnosis records at different time points
- **Export Function**: Support exporting historical diagnosis records

#### 诊断报告生成
- **结构化报告**: 生成包含症状、可能疾病、建议药品、注意事项的结构化报告
- **PDF导出**: 支持导出PDF格式的诊断报告
- **报告分享**: 支持分享诊断报告给医生或家属
- **报告存档**: 诊断报告自动存档，方便后续查阅
- **Structured Report**: Generate structured reports including symptoms, possible diseases, recommended drugs, precautions
- **PDF Export**: Support exporting diagnostic reports in PDF format
- **Report Sharing**: Support sharing diagnostic reports with doctors or family members
- **Report Archiving**: Diagnostic reports are automatically archived for future reference

#### 诊断反馈机制
- **准确性反馈**: 用户可对诊断结果进行准确/不准确反馈
- **反馈统计**: 统计诊断准确率，用于模型优化
- **模型微调**: 基于反馈数据持续优化AI模型
- **Accuracy Feedback**: Users can provide accurate/inaccurate feedback on diagnosis results
- **Feedback Statistics**: Statistics on diagnosis accuracy for model optimization
- **Model Fine-tuning**: Continuously optimize AI model based on feedback data

#### AI诊断功能
- **文本交流**: 用户描述症状，AI提供诊断建议
- **图片识别**: 支持上传图片进行病情识别
- **技能库**: 整合医生诊断案例为"skills"
- **模型集成**: 集成主流大模型（GPT、通义千问等）
- **模型微调**: 基于实际使用数据持续优化模型
- **Text Communication**: Users describe symptoms, AI provides diagnostic advice
- **Image Recognition**: Supports uploading images for disease recognition
- **Skills Library**: Integrates doctor diagnostic cases as "skills"
- **Model Integration**: Integrates mainstream large models (GPT, Tongyi Qianwen, etc.)
- **Model Fine-tuning**: Continuously optimize model based on actual usage data

### 6. 疾病管理模块 / Disease Management Module

#### 疾病信息管理
- **信息完整**: 名称、原因、症状、分类、预防措施
- **关联药品**: 每种疾病关联建议药品
- **状态管理**: 待审核、已通过、已拒绝状态
- **版本控制**: 支持疾病信息的更新历史
- **Complete Information**: Name, cause, symptoms, classification, preventive measures
- **Associated Drugs**: Each disease associated with recommended drugs
- **Status Management**: Pending review, approved, rejected statuses
- **Version Control**: Supports update history for disease information

#### 疾病搜索功能
- **全文检索**: 基于Elasticsearch的全文检索能力
- **智能补全**: 输入时智能补全疾病名称
- **分类筛选**: 按疾病分类筛选
- **热门排序**: 按浏览量、搜索次数排序
- **Full-text Search**: Full-text search capability based on Elasticsearch
- **Smart Completion**: Intelligent completion of disease names during input
- **Category Filtering**: Filter by disease category
- **Popularity Sorting**: Sort by page views, search frequency

### 7. 药品管理模块 / Drug Management Module

#### 药品信息管理
- **基本信息**: 药品名称、通用名、商品名
- **详细说明**: 功效、用法用量、注意事项
- **分类管理**: 按药品类型（处方药、非处方药等）分类
- **关联疾病**: 药品可关联多个适用疾病
- **Basic Information**: Drug name, generic name, brand name
- **Detailed Description**: Efficacy, usage, dosage, precautions
- **Category Management**: Classified by drug type (prescription, OTC, etc.)
- **Associated Diseases**: Drugs can be associated with multiple applicable diseases

#### 药品搜索功能
- **全文检索**: 基于Elasticsearch的全文检索能力
- **多维度搜索**: 名称、关键词、功效搜索
- **智能推荐**: 根据疾病自动推荐相关药品
- **使用统计**: 记录药品被推荐的次数
- **Full-text Search**: Full-text search capability based on Elasticsearch
- **Multi-dimensional Search**: Name, keywords, efficacy search
- **Intelligent Recommendation**: Automatically recommends related drugs based on diseases
- **Usage Statistics**: Records how many times drugs are recommended

### 8. 科研管理模块 / Research Management Module

#### 科研成果管理
- **成果发布**: 医生可以发布最新医学研究成果
- **成果审核**: 管理员审核科研成果的准确性和价值
- **成果分类**: 按研究领域、疾病类型等分类
- **成果应用**: 优秀成果可转化为AI技能
- **Research Publication**: Doctors can publish latest medical research results
- **Research Review**: Administrators review accuracy and value of research results
- **Research Classification**: Classified by research field, disease type, etc.
- **Research Application**: Excellent results can be converted into AI skills

#### 纠错反馈
- **内容纠错**: 医生可以纠正疾病、药品信息的错误
- **AI纠错**: 医生可以指出AI诊断的错误
- **反馈跟踪**: 跟踪纠错反馈的处理状态
- **Content Correction**: Doctors can correct errors in disease, drug information
- **AI Correction**: Doctors can point out errors in AI diagnosis
- **Feedback Tracking**: Tracks processing status of correction feedback

### 9. 内容审核模块 / Content Review Module

#### 审核工作台
- **待审核列表**: 展示待审核的疾病、药品、科研成果
- **审核操作**: 支持通过、拒绝、退回修改等操作
- **审核记录**: 记录所有审核操作历史
- **批量审核**: 支持批量审核操作
- **Pending Review List**: Display pending diseases, drugs, research results
- **Review Operations**: Support approve, reject, return for modification operations
- **Review Records**: Record all review operation history
- **Batch Review**: Support batch review operations

#### 审核流程
- **提交审核**: 医生提交内容后进入待审核状态
- **分级审核**: 根据内容类型分配不同审核人员
- **审核通知**: 审核结果通知提交者
- **Submit for Review**: Content enters pending review status after doctor submission
- **Hierarchical Review**: Assign different reviewers based on content type
- **Review Notification**: Notify submitter of review results

### 10. 诊疗统计模块 / Diagnosis Statistics Module

#### 统计数据
- **诊疗量统计**: 统计医生的诊断次数
- **患者满意度**: 统计患者对诊断的满意度
- **诊断准确率**: 基于用户反馈统计诊断准确率
- **趋势分析**: 分析诊疗数据的变化趋势
- **Diagnosis Volume Statistics**: Statistics on doctor's diagnosis count
- **Patient Satisfaction**: Statistics on patient satisfaction with diagnosis
- **Diagnostic Accuracy**: Statistics on diagnostic accuracy based on user feedback
- **Trend Analysis**: Analyze trends in diagnosis data

#### 数据展示
- **数据看板**: 可视化展示诊疗统计数据
- **报表导出**: 支持导出统计报表
- **对比分析**: 支持不同时间段的对比分析
- **Data Dashboard**: Visual display of diagnosis statistics
- **Report Export**: Support exporting statistical reports
- **Comparison Analysis**: Support comparison analysis of different time periods

### 11. 反馈管理模块 / Feedback Management Module

#### 用户反馈
- **反馈提交**: 用户可以提交系统使用反馈
- **反馈分类**: 按问题类型（功能建议、bug报告等）分类
- **反馈处理**: 管理员查看并处理用户反馈
- **邮件回复**: 管理员可以通过邮件感谢用户反馈
- **Feedback Submission**: Users can submit system usage feedback
- **Feedback Classification**: Classified by problem type (feature suggestions, bug reports, etc.)
- **Feedback Processing**: Administrators view and process user feedback
- **Email Reply**: Administrators can thank users for feedback via email

### 12. 系统主页模块 / System Homepage Module

#### 内容展示
- **最新资讯**: 展示最新的医疗资讯和科研成果
- **热门疾病**: 展示浏览量最高的疾病
- **常用药品**: 展示最常用的药品
- **使用指南**: 提供系统使用说明和帮助
- **Latest News**: Displays latest medical news and research results
- **Popular Diseases**: Displays diseases with highest page views
- **Common Drugs**: Displays most commonly used drugs
- **Usage Guide**: Provides system usage instructions and help

## 非功能需求 / Non-functional Requirements

### 1. 性能需求 / Performance Requirements
- **响应时间**: 页面加载时间 < 3秒，API响应时间 < 2秒，Elasticsearch搜索 < 1秒
- **并发用户**: 支持1000+并发用户
- **数据容量**: 支持百万级疾病/药品数据，千万级诊断记录
- **搜索性能**: Elasticsearch支持每秒1000+查询
- **Response Time**: Page load time < 3 seconds, API response time < 2 seconds, Elasticsearch search < 1 second
- **Concurrent Users**: Supports 1000+ concurrent users
- **Data Capacity**: Supports millions of disease/drug data, tens of millions of diagnosis records
- **Search Performance**: Elasticsearch supports 1000+ queries per second

### 2. 安全性需求 / Security Requirements
- **数据安全**: 用户医疗数据加密存储，敏感数据脱敏处理
- **访问控制**: 基于角色的细粒度权限控制
- **操作审计**: 记录所有关键操作日志，支持审计追溯
- **防攻击**: 防止SQL注入、XSS等常见攻击
- **合规认证**: 符合等保二级/三级要求
- **隐私计算**: 探索联邦学习等隐私保护技术
- **Data Security**: User medical data encrypted storage, sensitive data desensitized
- **Access Control**: Role-based fine-grained permission control
- **Operation Audit**: Records all critical operation logs, supports audit traceability
- **Attack Prevention**: Prevents common attacks like SQL injection, XSS
- **Compliance Certification**: Meets Level 2/3 Protection requirements
- **Privacy Computing**: Explores privacy protection technologies like federated learning

### 3. 可用性需求 / Usability Requirements
- **界面友好**: 简洁直观的用户界面
- **操作简便**: 减少用户操作步骤
- **响应式设计**: 支持PC和移动端访问
- **帮助文档**: 提供完善的帮助文档
- **User-Friendly Interface**: Simple and intuitive user interface
- **Easy Operation**: Reduces user operation steps
- **Responsive Design**: Supports PC and mobile access
- **Help Documentation**: Provides comprehensive help documentation

### 4. 可靠性需求 / Reliability Requirements
- **系统可用性**: 99.9%的系统可用性
- **数据备份**: 定期备份关键数据，支持自动化备份
- **故障恢复**: 支持快速故障恢复
- **监控告警**: 实时监控系统状态
- **数据归档**: 定期归档过期数据，保持主库性能
- **System Availability**: 99.9% system availability
- **Data Backup**: Regular backup of critical data, supports automated backup
- **Fault Recovery**: Supports rapid fault recovery
- **Monitoring Alerts**: Real-time system status monitoring
- **Data Archiving**: Periodic archiving of expired data, maintain primary database performance

### 5. 数据同步机制 / Data Synchronization Mechanism

#### MySQL到Elasticsearch同步
- **同步方式**: Canal + Kafka + 消费者
- **同步策略**: 实时同步，确保数据一致性
- **异常处理**: 同步失败重试机制，死信队列处理
- **监控告警**: 同步延迟监控，异常告警
- **Synchronization Method**: Canal + Kafka + Consumer
- **Synchronization Strategy**: Real-time synchronization to ensure data consistency
- **Exception Handling**: Synchronization failure retry mechanism, dead letter queue processing
- **Monitoring Alerts**: Synchronization delay monitoring, anomaly alerts

#### 冷热数据分离策略
- **热数据**: 最近6个月的诊断记录，存储在MySQL
- **温数据**: 6-24个月的诊断记录，存储在只读从库
- **冷数据**: 超过24个月的诊断记录，归档至对象存储
- **归档策略**: 每月自动归档，支持手动触发
- **Hot Data**: Diagnosis records from last 6 months, stored in MySQL
- **Warm Data**: Diagnosis records from 6-24 months, stored in read-only slave
- **Cold Data**: Diagnosis records over 24 months, archived to object storage
- **Archiving Strategy**: Automatic monthly archiving, supports manual triggering
