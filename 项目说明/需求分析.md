## 1. 引言

### 1.1 文档目的

本文档旨在全面描述智慧医院系统的业务需求、功能需求和非功能需求，为项目开发、测试和验收提供依据。通过本需求分析文档，开发团队能够清晰理解系统目标和用户需求，确保最终交付的系统满足用户期望。

### 1.2 项目背景

智慧医院系统是一个基于人工智能和大数据技术的医疗辅助平台，旨在为学校、工厂、监狱等不方便前往医院的人群提供便捷、安全的医疗服务。该系统响应了以下社会需求：

- **医疗资源分布不均**：偏远地区和特殊场所人员难以获得及时医疗服务
- **就医门槛高**：时间成本和交通成本限制了小病患者及时就医
- **医疗信息不对称**：用户缺乏医学知识，难以准确描述症状
- **数据安全隐患**：医疗数据涉及用户隐私，需要严格的保护措施

### 1.3 目标与范围

**项目目标**：
- 构建一套完整的AI医疗辅助系统，实现智能化病情诊断
- 建立个人健康档案体系，为用户提供持续性健康管理
- 提供多渠道医疗服务，降低用户就医门槛
- 建立严格的数据安全保障体系，确保用户隐私安全

**项目范围**：
- 涵盖用户端、医生端、管理员端三大用户群体
- 支持PC端和移动端访问
- 集成主流AI大模型能力
- 包含完善的后台管理系统

### 1.4 术语与定义

| 术语 | 定义 |
|------|------|
| AI医生 | 基于大语言模型的智能诊断助手，能够理解用户描述并提供诊断建议 |
| Skills | 医生诊断案例转化而来的结构化诊断知识库 |
| 健康档案 | 用户个人完整的医疗健康信息记录 |
| 诊断记录 | 用户与AI医生交互产生的诊断会话记录 |
| 症状自测 | 通过结构化问卷引导用户评估健康状况的功能 |
| 冷热数据 | 热数据为近期频繁访问的数据，冷数据为历史归档数据 |
| 数据脱敏 | 对敏感信息进行变形处理以保护隐私的技术 |
| 操作审计 | 记录和分析系统操作行为的安全机制 |

## 2. 项目概述

### 2.1 项目简介

智慧医院系统整合了医生诊断案例，将其转化为"skills"并植入主流大模型中，实现精准的病情判断。系统采用微服务架构设计，基于Java和Vue.js技术栈开发，支持高并发访问和数据安全保障。

### 2.2 核心价值主张

| 价值维度 | 具体描述 |
|----------|----------|
| **便捷性** | 用户可随时随地通过系统获取医疗咨询，无需排队等候 |
| **智能性** | AI医生能够理解复杂症状描述，提供个性化诊断建议 |
| **完整性** | 健康档案管理提供持续性健康管理服务 |
| **安全性** | 严格的数据安全保障体系，确保医疗信息安全 |
| **专业性** | 医生专家参与内容审核，确保信息准确性 |

### 2.3 系统边界

**系统包含**：
- 用户健康管理功能（健康档案、症状自测、用户收藏）
- AI智能诊断功能（多轮对话、历史诊断、诊断报告、反馈机制）
- 医疗内容管理功能（疾病管理、药品管理、科研成果管理）
- 医生协作功能（诊疗统计、内容审核、患者档案查看）
- 系统管理功能（用户管理、反馈管理、日志审计）
- 数据支撑功能（Elasticsearch搜索、数据同步、冷热分离）

**系统不包含**：
- 实际药品销售和配送功能
- 线下医院预约挂号对接
- 医保结算功能
- 紧急医疗服务（120联动）

### 2.4 系统约束

| 约束类型 | 具体约束 |
|----------|----------|
| **技术约束** | 必须使用Java和Vue.js技术栈 |
| **法规约束** | 需符合等保二级/三级安全要求 |
| **数据约束** | 用户数据需在境内存储 |
| **时间约束** | 项目周期为13周 |
| **资源约束** | 团队规模为8人 |

| 特殊需求 | 界面简洁，操作直观，无需学习成本 |

### 4.2 用户管理模块

#### 4.2.1 模块概述

用户管理模块是系统的基础模块，负责用户的注册、登录、身份认证和权限管理。该模块为所有业务功能提供用户身份支撑。

#### 4.2.2 功能列表

| 功能编号 | 功能名称 | 功能描述 | 业务规则 |
|----------|----------|----------|----------|
| UM-001 | 用户注册 | 用户填写信息完成注册 | 1. 支持邮箱注册<br>2. 注册时需验证邮箱<br>3. 医生注册需验证执业资格 |
| UM-002 | 用户登录 | 用户使用账号密码登录 | 1. 支持用户名或邮箱登录<br>2. 连续5次失败锁定15分钟<br>3. 支持JWT令牌认证 |
| UM-003 | 密码找回 | 用户通过邮箱找回密码 | 1. 发送重置链接至注册邮箱<br>2. 链接有效期30分钟 |
| UM-004 | 个人信息管理 | 用户查看和修改个人信息 | 1. 医生必须使用真实姓名<br>2. 头像支持JPG/PNG格式，不超过2MB |
| UM-005 | 密码修改 | 用户修改登录密码 | 1. 需验证原密码<br>2. 新密码不能与原密码相同 |
| UM-006 | 权限控制 | 基于角色的功能访问控制 | 1. 四级角色：游客、用户、医生、管理员<br>2. 菜单和数据权限分离控制 |

### 4.3 健康档案模块

#### 4.3.1 模块概述

健康档案模块为用户提供个人医疗健康信息的完整管理功能。健康档案是AI诊断的重要参考依据，能够帮助AI医生更准确地理解用户的健康状况。

#### 4.3.2 功能列表

| 功能编号 | 功能名称 | 功能描述 | 业务规则 |
|----------|----------|----------|----------|
| HR-001 | 创建健康档案 | 用户首次创建个人健康档案 | 1. 每位用户仅能创建一个档案<br>2. 档案创建后不可删除 |
| HR-002 | 编辑病史记录 | 添加或修改既往病史 | 1. 支持添加多条病史记录<br>2. 记录需包含发病时间、诊断结果、治疗情况 |
| HR-003 | 编辑过敏史 | 添加或修改过敏信息 | 1. 区分药物过敏和食物过敏<br>2. 记录过敏反应症状 |
| HR-004 | 编辑用药记录 | 添加或修改用药历史 | 1. 记录正在使用和曾使用的药物<br>2. 包含剂量和用药时长 |
